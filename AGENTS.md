# Презентации на Slidev

Шаблон репозитория для набора презентаций на [Slidev](https://sli.dev): доклады,
лекции, воркшопы, внутренние встречи.

Этот файл — единственный источник проектных соглашений, общий для всех
AI-агентов ([стандарт agents.md](https://agents.md)). Участники работают
разными инструментами, поэтому правила живут здесь, а не в файле под конкретного
агента. `CLAUDE.md` — короткая отсылка сюда.

## Структура

```
presentations/<NN-название>/ презентация: slides.md (оглавление) + sections/ (содержание)
shared/                 общие лейауты, компоненты и стили (Slidev-аддон)
apps/                   демо-приложения (если нужны)
scripts/                обёртки запуска; shared.mjs — что считается презентацией
.claude/skills/slidev/  официальный skill Slidev (копия, см. UPSTREAM.md)
```

`apps/` пока пуст — демо-приложения заводятся по необходимости. Из проверок
качества их сейчас покрывает только ESLint: добавляя первое приложение,
заведите для него собственные проверки (типы, сборка, тесты) и включите
их в `pnpm check`.

## Команды

```bash
pnpm install               # первый шаг после клона
pnpm slides:list           # список презентаций
pnpm slides 01-demo        # запустить (:3030; занят — следующий)
pnpm slides:new 02-basics  # создать новую презентацию
pnpm build 01-demo         # собрать одну
pnpm build:all             # собрать все в dist/
pnpm export 01-demo        # PDF (нужен браузер: npx playwright install chromium)
```

Есть ещё две точки входа поверх этих же скриптов: задачи VS Code
(`Ctrl+Shift+P` → «Tasks: Run Task») и `Makefile` (`make help`).
Канонический путь — `pnpm`: он работает везде и ничего не требует.

**Новую презентацию создавайте генератором, а не копированием папки.** Он подставляет
номер и заголовок и подключает общие блоки — забыть `addons: [../shared]`
невозможно, а без него блоки молча не работают.

**Правило «что такое презентация» живёт только в `scripts/shared.mjs`.** Не дублируйте
эту логику в новых скриптах — импортируйте `listPresentations()` оттуда.

## Проверки качества

```bash
pnpm check           # всё сразу: слайды, генератор, код, типы, орфография, формат, сборка
pnpm lint:content    # только разметка презентаций (быстро)
pnpm test:generator  # шаблон новой презентации проходит проверки
pnpm lint:fix        # автоисправление кода
pnpm format          # форматирование слайдов
```

Перед коммитом автоматически запускаются `lint:content`, проверки staged-файлов,
`typecheck` и сборка затронутых презентаций. Перед push собираются все презентации
(`pnpm build:all`). CI у репозитория нет, хуки — единственный автоматический
рубеж. Обойти — `--no-verify` (но тогда сломанное уедет всей команде).

Правка `shared/` затрагивает все презентации, но на коммите собирается только одна:
полный прогон при 10–15 презентациях занимал бы минуты. Все презентации проверяются
на push — там же выяснится, если общий компонент сломал какую-то из них.

Pre-push собирает все презентации **всегда**, даже если менялся только README:
разбирать, что попало в пушимый диапазон, дороже и ненадёжнее, чем собрать.
Если push срочный, а правка заведомо не трогает слайды — `git push --no-verify`.

**Хуки читают рабочее дерево, а не staged-снимок.** Если после `git add`
поправить файл и не сделать `add` повторно, проверки пройдут по новой версии,
а в коммит уедет старая. Практическое правило: закончили правки — `git add`,
и только потом `commit`.

Что чем проверяется:

| Инструмент | Область | Ловит |
| --- | --- | --- |
| `lint-content.mjs` | `presentations/**` | грабли Slidev, которые проходят сборку молча: опечатки в лейаутах и компонентах, битый frontmatter, незакрытые код-блоки, мёртвые ссылки и др. |
| `test-generator.mjs` | шаблон в `new-slides.mjs` | дефекты, из-за которых новая презентация не проходит `check` |
| ESLint | `scripts/`, `shared/`, конфиги | ошибки и стиль кода (с автофиксом) |
| `vue-tsc` | `shared/**/*.vue` | типы в пропсах компонентов |
| cspell | `presentations/**` | опечатки; словарь проекта — `.cspell/project.txt` |
| Prettier | только `presentations/**/*.md` | форматирование слайдов |
| `build:all` | все презентации | ошибки шаблонов и путей |

Prettier настроен **только на слайды** — код форматирует ESLint. Два форматтера
на одних файлах устроили бы войну правок.

Незнакомое слово в слайде — добавьте в `.cspell/project.txt`, одно на строку.

**Правя шаблон новой презентации в `scripts/new-slides.mjs`, запустите
`pnpm test:generator`.** Шаблон лежит там строковым литералом: ESLint видит его
как строку, а cspell и Prettier проверяют только `presentations/**`, где
сгенерированного ещё нет. Опечатка или лишний отступ в шаблоне не всплывут
нигде — но сломают `pnpm check` тому, кто создаст новую презентацию. Незнакомое
слово из текста шаблона тоже идёт в `.cspell/project.txt`.

## Правила, которые легко нарушить

Всё ниже проверено на практике — это не теория, а грабли, дающие либо ошибку
сборки, либо молчаливый дефект в презентации. Все они ловятся
`pnpm lint:content`, но знать их всё равно полезно.

**Путь к общим блокам — `../shared`, а не `../../shared`.** Slidev резолвит
аддон как `resolve(dirname(userRoot), path)`, где `userRoot` — папка презентации.
Лишний уровень «съедается», путь оказывается вне репозитория.

**Файл секции начинается сразу с `---`.** Всё, что стоит до первого
разделителя, — это уже слайд. Комментарий-заголовок файла создаст пустой слайд
в презентации, а сборка при этом пройдёт успешно.

**Последовательность `---` не должна начинать строку — даже внутри
HTML-комментария.** Slidev режет файл на слайды поиском по тексту, до разбора
Markdown и YAML: комментарии он при этом не исключает. Во frontmatter такая
строка обрывает его, и остаток становится телом слайда, откуда берётся
заголовок; в теле слайда — разрывает файл на лишние слайды. Многострочные
комментарии сами по себе безопасны — дело именно в `---` с начала строки.
Если нужно показать разделитель в примере внутри комментария, опишите его
словами или сделайте отступ.

Отдельный случай — **`---` внутри значения frontmatter** (`subtitle: Экосистема
--- инструменты`): здесь позиция в строке уже не важна. Значение молча
обрезается по разделителю, а следующие ключи теряются. `pnpm lint:content`
ловит оба случая; чинить нужно именно текст, а не форматированием.

**Внутри слайда слоты задаются через `<template #name>`.** Сокращение
`::name::` — сахар только для слотов лейаута; внутри слайда оно ломает сборку
с ошибкой `Element is missing end tag`.

**Двойные фигурные скобки в тексте — это интерполяция Vue.** Если нужно
показать их как текст, заворачивайте в инлайн-код.

**`download: true` в headmatter не включаем.** Иначе обычная сборка тянет
за собой генерацию PDF и требует скачанный браузер Playwright у каждого.

## Работа со слайдами

Для операций уровня слайда (вставить, удалить, переместить, поправить заметку)
**предпочитайте инструменты MCP-сервера Slidev** текстовому редактированию:
они корректно обрабатывают разделители и не ломают структуру презентации.

Ограничения, о которых нужно знать:

- Слайды адресуются сквозными номерами по всей презентации, а не по файлам
- Слайды из `src:` правятся в своих файлах
- `slidev-move-slide` **не перемещает слайды между файлами** — перенос из одной
  секции в другую делается вручную
- Первый слайд `slides.md` удалить нельзя: его frontmatter (headmatter) — это
  одновременно конфигурация всей презентации и настройки титульного слайда

MCP-сервер настроен в `.mcp.json` (stdio-режим, работает без dev-сервера).

**Внимание: в `.mcp.json` жёстко задана презентация `01-demo`.** Команда `slidev mcp`
требует конкретный файл и не умеет определять его сама. Работая над другой
презентацией, переключите её командой `pnpm mcp <имя>` (перепишет `.mcp.json`)
и перезапустите Claude Code — иначе MCP-инструменты будут молча править
файлы первой презентации.

Если нужна навигация по запущенной презентации, подключите HTTP-вариант — он
берёт презентацию из работающего dev-сервера, поэтому хардкода не требует:

```bash
claude mcp add --transport http slidev http://localhost:3030/__mcp
```

В `.claude/settings.json` включён `enableAllProjectMcpServers` — MCP-серверы
из `.mcp.json` стартуют без подтверждения у каждого. Сделано осознанно: сейчас
там один локальный сервер из `node_modules`, и лишний вопрос на старте только
мешал бы. **Добавление нового MCP-сервера в `.mcp.json` — изменение, требующее
ревью:** оно включится у всех автоматически, в том числе из чужого коммита.

## Общие блоки

Живут в `shared/` и подключаются автоматически — импортировать не нужно.

### Лейауты

| Лейаут | Назначение | Параметры |
| --- | --- | --- |
| `cover` | Титульный слайд | `badge` или `number`, `subtitle`, `duration` |
| `section` | Разделитель смысловых блоков | `step` |

```md
---
layout: cover
badge: Доклад
subtitle: Подзаголовок
duration: 90min
---
```

`badge` — готовый текст метки. Для серии (курс, цикл встреч) удобнее номер:
задайте `badgeLabel` в `shared/project.json` один раз, а в презентации — только
`number: 3`, и на слайде появится «Лекция 3».

`duration` — **зарезервированный ключ Slidev**: то же значение читает таймер
презентатора. Формат латинский (`90min`, `1h30min`), на слайде лейаут покажет
его по-русски. Кириллица (`90 мин`) молча ломает таймер: парсер вернёт `null`.

Для **титульного слайда** эти ключи идут прямо в headmatter `slides.md`:
headmatter одновременно служит frontmatter'ом первого слайда, отдельного
блока настроек для него не существует. Заводить второй титульный слайд
в первой секции не нужно — получится дубль.

### Компоненты

| Компонент | Назначение |
| --- | --- |
| `<Task>` | Практическое задание (`title`, `duration`) |
| `<Checklist>` | Критерии приёмки или итоги (`title`, `:items`) |
| `<CodeExplain>` | Код слева, пояснение справа (`ratio`) |
| `<Note>` | Врезка: `info` (по умолчанию), `warn`, `danger`, `tip` |

```md
<Task title="Первый компонент" duration="20 мин">

Создайте компонент через Angular CLI.

</Task>

<Checklist :items="['Компонент создан', 'Подключён в imports']" />

<Note type="warn" title="Частая ошибка">
Забытый `standalone: true`.
</Note>
```

В `<CodeExplain>` пояснение задаётся через `<template #explain>` с пустыми
строками вокруг содержимого:

````md
<CodeExplain>

```ts
const answer = 42
```

<template #explain>

Пояснение к коду.

</template>

</CodeExplain>
````

**Новый переиспользуемый блок добавляйте в `shared/`**, а не копируйте разметку
между презентациями — ради этого архитектура и построена на аддоне.

## Соглашения

- Все материалы и комментарии — на русском; технические термины и идентификаторы
  оставляем как есть
- Секция — 3–10 слайдов, один смысловой блок: так проще ревьюить и меньше
  конфликтов в git. Верхняя граница важнее нижней: если слайдов больше десяти,
  почти всегда внутри два разных блока
- Стили компонентов держим внутри `.slidev-layout`, иначе они протекают
  в интерфейс режима презентатора
- Скрипты запуска — на Node, не на shell: участники работают на разных ОС

## Skill Slidev

`.claude/skills/slidev/` — копия официального skill (53 reference-файла).
Не редактируйте его содержимое: правки потеряются при обновлении, а проектные
соглашения место здесь, в `AGENTS.md`. Как обновлять — в
`.claude/skills/slidev/UPSTREAM.md`.

Upstream-skill местами советует команды, которых в этом репозитории нет
(например, `pnpm run dev`): запуск презентаций — только `pnpm slides <имя>`,
см. раздел «Команды».

Skill и MCP-сервер — инструменты Claude Code. Работая другим агентом,
ориентируйтесь на разделы выше: соглашения и грабли от инструмента не зависят.
