# Презентации на Slidev

Шаблон репозитория для набора презентаций: доклады, лекции, воркшопы,
внутренние встречи. Слайды пишутся в markdown, переиспользуемые блоки —
на Vue ([Slidev](https://sli.dev)).

Из коробки: генератор презентаций, общие лейауты и компоненты, проверки
качества, dev-контейнер, экспорт в PDF и статическую раздачу.

## Быстрый старт

Нужен Node.js ≥ 22.13 и pnpm. Рекомендуемая версия Node — в `.nvmrc`
(на ней проверены все команды); более ранние отвергнет сам pnpm.

```bash
pnpm install          # версии Node и pnpm проверятся автоматически
pnpm slides 01-demo   # http://localhost:3030
```

Порт 3030 занят (например, второй презентацией)? Slidev возьмёт следующий
свободный — фактический адрес смотрите в баннере запуска.

Если pnpm не установлен, поставьте его напрямую:

```bash
npm install -g pnpm
```

Corepack (`corepack enable`) тоже подойдёт и возьмёт версию pnpm из
`package.json`, но работает не везде: на Node 25+ он не входит в поставку,
а на Node 22.13–22.x падает ошибкой «Cannot find matching keyid» —
там сначала нужен `npm install -g corepack@latest`. С версией Node
из `.nvmrc` таких хлопот нет.

Установка через `npm install` или `yarn` не подойдёт: проект завязан на
pnpm-workspace и остановится с ошибкой (npm — не сразу, а после того как
скачает дерево зависимостей). Если запустить `npm install` поверх готовой
pnpm-установки, ошибка будет англоязычной и невнятной (`ERESOLVE`) — это
то же самое, просто npm спотыкается раньше. Лечится `pnpm install`.

## Что заполнить под себя

| Файл | Что там |
| --- | --- |
| `shared/project.json` | название проекта, автор, заголовок вкладки |

Эти файлы принадлежат проекту и не перезаписываются при обновлении
инфраструктуры из шаблона — подробности в [docs/TEMPLATE.md](docs/TEMPLATE.md).

## Команды

| Команда | Что делает |
| --- | --- |
| `pnpm slides:list` | список презентаций |
| `pnpm slides <имя>` | запустить (dev-сервер, hot-reload) |
| `pnpm slides:new <имя>` | создать новую презентацию |
| `pnpm build <имя>` | собрать одну |
| `pnpm build:all` | собрать все в `dist/` |
| `pnpm export <имя>` | экспортировать в PDF |
| `pnpm check` | все проверки качества |

Для экспорта в PDF один раз поставьте браузер и его системные библиотеки:

```bash
sudo npx playwright install-deps chromium   # системные библиотеки (нужен sudo)
npx playwright install chromium             # сам браузер
```

Без первой команды браузер скачается, но не запустится — экспорт упадёт
с `error while loading shared libraries: libnspr4.so`.

В dev-контейнере обе команды выполняются автоматически: включите флаг
`INSTALL_PLAYWRIGHT_BROWSER=true` в `.devcontainer/.env` и пересоберите
контейнер.

### Другие способы запуска

Всё то же самое доступно ещё двумя путями — выбирайте привычный:

- **Задачи VS Code** — `Ctrl+Shift+P` → «Tasks: Run Task». Имя презентации
  спрашивается при запуске. Ничего ставить не нужно.
- **Make** — `make help` покажет список. Имя передаётся любым способом:
  `make slides 01-demo` или `make slides NAME=01-demo`.
  На Windows `make` требует отдельной установки, поэтому это опция, а не основной путь.

Все три — тонкие обёртки над одними и теми же скриптами в `scripts/`.

## Выступление

Презентация читается с того же dev-сервера, что и при подготовке:
`pnpm slides 01-demo`.

**Режим презентатора** — добавьте `/presenter` к адресу
(`http://localhost:3030/presenter`) или нажмите кнопку в панели внизу слайда.
Отдельной клавиши для него нет. В этом режиме видны заметки к слайду,
следующий слайд и таймер.

Удобно открыть два окна: презентаторское — себе, обычное — на проектор.
Слайды синхронизируются автоматически.

**Клавиши во время показа:**

| Клавиша | Действие |
| --- | --- |
| `Пробел`, `→` | вперёд (по шагам анимации) |
| `Shift+Пробел`, `←` | назад |
| `Shift+→`, `Shift+←` | следующий/предыдущий слайд целиком |
| `↑` `↓` | по слайдам, минуя шаги анимации |
| `o` или `` ` `` | обзор всех слайдов, `Esc` — выйти |
| `g` | перейти к слайду по номеру |
| `d` | переключить тёмную тему |
| `f` | полноэкранный режим |

Длительность для таймера задаётся в headmatter: `duration: 90min`
(формат Slidev — латинские единицы; на слайде покажется «90 мин»).

**Рисование поверх слайдов** — кнопка с карандашом в той же панели.
По умолчанию рисунки не сохраняются между запусками
(`drawings.persist: false` в headmatter).

**Заметки** пишутся HTML-комментарием в конце слайда — они не попадают
на проектор и видны только в режиме презентатора.

Если выступать нужно без сервера, соберите статику (`pnpm build 01-demo`)
или PDF (`pnpm export 01-demo`).

## Проверки качества

```bash
pnpm check
```

Семь ступеней: разметка слайдов, шаблон генератора, код, типы, орфография,
форматирование, сборка. Перед коммитом основные запускаются автоматически,
перед push собираются все презентации.

Что чем проверяется и почему — в [AGENTS.md](AGENTS.md).

## Структура

```
presentations/     презентации: одна папка — одна презентация
  01-demo/
    slides.md      точка входа: настройки + титульный слайд
    sections/      секции, подключаются через src:
shared/            общие лейауты, компоненты, стили
  project.json     название проекта, автор
scripts/           запуск, генератор, проверки
apps/              демо-приложения (пусто, если не нужны)
docs/              документация репозитория
```

## Новая презентация

```bash
pnpm slides:new 02-basics
pnpm slides:new 02-basics --title "Основы: типы и структуры"
```

Имя — две цифры, дефис, латиница. Русский заголовок задаётся через `--title`.
Генератор создаёт каркас с подключёнными общими блоками и первой секцией.

## Общие блоки

Живут в `shared/` и подключаются автоматически — импортировать не нужно.

| Блок | Назначение |
| --- | --- |
| `layout: cover` | титульный слайд: метка, длительность, подзаголовок, футер |
| `layout: section` | разделитель смысловых блоков |
| `<Note>` | акцентная врезка: `info`, `tip`, `warn`, `danger` |
| `<Checklist>` | список с галочками |
| `<Task>` | выделенный блок с заданием |
| `<CodeExplain>` | код слева, пояснение справа |

Примеры использования — в демо-презентации и в [AGENTS.md](AGENTS.md).

## Обновление инфраструктуры

Репозиторий создан из шаблона. Чтобы получить улучшения инфраструктуры
(скрипты, проверки, общие блоки), запустите Actions → «Обновление
из шаблона» → Run workflow. Изменения придут отдельным pull request'ом.

Содержание презентаций и файлы проекта при этом не трогаются — что именно
синхронизируется, описано в [docs/TEMPLATE.md](docs/TEMPLATE.md).

## Разное окружение

Участники работают на разных системах и разными инструментами, поэтому:

- версии Node и pnpm фиксируются в `package.json` и проверяются при установке
- переводы строк приведены к LF через `.gitattributes`
- скрипты запуска написаны на Node, а не на shell
- есть dev-контейнер: VS Code → **Reopen in Container**
